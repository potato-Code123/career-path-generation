# Course Planner

A minimalist web app over the extracted CMU data: plan a four-year degree, build
a Fall 2026 schedule, and browse general education requirements.

## Run

```bash
python build_site.py          # from cmu-catalog/, refreshes site/data/
python site/serve.py          # http://localhost:8151
```

No dependencies, no build step — plain ES modules and CSS. `serve.py` sends
`Cache-Control: no-store` because http.server's default caching makes the
browser keep executing stale modules after an edit.

## Tabs

**Degree** — eight terms, a requirement checklist that ticks itself off, and
prerequisite checking against everything scheduled in earlier terms. Click any
requirement to see only the courses that satisfy it, pick one, and choose a
term. 201 degrees available.

**Schedule** — a weekly grid for Fall 2026 from the Schedule of Classes. Time
conflicts are flagged and laid out side by side, never blocked: overlapping
sections split the column so both stay readable, and the banner names the clash.

**Gen Eds** — categories for the school implied by your degree, defaulting to
the courses that actually run in Fall 2026. Exclusion lists (SCS "Deletions",
CIT "Free Elective Only") are badged **Does not count** rather than mixed in
with approved courses.

Press `/` anywhere for course search. Plan and schedule persist in
localStorage.

## How the judgement calls were made

**Prerequisites are evaluated as boolean trees, not edge lists.** `15-451`
needs `15-210 and 21-241 and (15-251 or 21-228)`; a flat list of four
prerequisites would be wrong. The graph in the course sheet draws the same
structure — outer operands joined by `and`, with the `or` group bracketed.

**Three states, not two.** A course is fine, missing a prerequisite, or
carries a condition that cannot be checked automatically ("senior standing",
"permission of instructor"). The third case is flagged amber and worded as
*check*, because claiming a violation there would be wrong as often as right.

**Requirement quantifiers are read from prose, and prose is kept.** Captions
say "all of the following", "minimum 5 courses", "select two". Those are parsed
into a rule, but the original caption is displayed next to it so a student can
see the real wording rather than only the interpretation.

**Prose-only groups are shown, not scored.** Some requirements — "Two School of
Computer Science electives" — describe the qualifying set in words with no
course list. They appear as reference notes and are left out of the progress
tally instead of sitting permanently at 0/0.

**Conflicts are advisory.** Students routinely plan around a partial overlap or
a section they intend to swap. The app says what clashes and leaves the choice
alone.

## Data

`site/data/` is generated by `build_site.py` from the extraction pipeline:

| file | contents |
|---|---|
| `courses.json` | 4,263 courses with prerequisite trees |
| `descriptions.json` | fetched lazily after first paint (3.4 MB) |
| `degrees.json` | 201 degrees, requirement groups, parsed rules |
| `offerings.json` | 3,327 Fall 2026 sections with meeting times |
| `geneds.json` | 34 categories, each course flagged for F26 |

## Known limits

- Gen-ed "offered in F26" is exact for CIT and Dietrich (their sources carry
  semester tags) and inferred from the Schedule of Classes for SCS and MCS,
  which publish none.
- The degree → school mapping for the Gen Eds tab is pattern-based; the picker
  overrides it and the choice sticks.
- Requirement rules come from prose and will be wrong for unusual phrasings.
  The caption is always shown so the real rule is one glance away.
- No instructors anywhere — no CMU source publishes them outside FCE.
